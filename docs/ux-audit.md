# 오하꼼 Figma UX 감사 및 구현 결정

기준 파일: Figma `hiARnhYIoAn2RCZnBck3cT`, Pages/Components 전체 보드.

## 유지한 디자인 시스템

- Noto Sans KR 400/500/700, 검정 `#161614`, 라임 `#D9F56A`, 퍼플 `#7767F7`, 아이보리 계열 배경.
- 20px 전후 카드 라운드, pill chip, 단정한 라인 아이콘, 넓은 여백과 짧은 설명 문장.
- 홈 → 단일 미션 → 출발 약속 → 이동 → 도착 기록의 핵심 구조.
- 내 지도, 활동 기록, 인사이트, 랭킹, 배지, 혜택, 설정의 정보 구조.

## 발견한 문제와 개선

1. 긴 화면의 주요 버튼이 콘텐츠 끝에 있어 작은 기기에서 놓치기 쉬움.
   - 행동 화면의 주 CTA를 안전영역 포함 고정 하단 full-width로 통일.
   - 스크롤 콘텐츠에 CTA 높이만큼 자동 여백을 확보.
2. 일부 아이콘 버튼의 시각 크기가 36px로 터치 영역이 작음.
   - 모든 주요 아이콘 버튼은 최소 44×44px, 의미 있는 접근성 라벨 제공.
3. 앱 시작 단계에서 위치 권한을 묻는 흐름은 신뢰와 전환에 불리함.
   - 미션을 선택하고 실제 출발하기 직전에만 요청.
   - 사용 이유, 보관 범위, QA 위치 우회를 같은 화면에서 설명.
4. 로그인 제공자가 많고 Kakao 중심 정책과 충돌.
   - Kakao 단일 주 로그인과 명확한 QA 우회만 유지.
   - 앱 키 발급 전에도 동일한 사용자 여정을 MSW로 검증 가능.
5. 랭킹의 공개 범위가 행동 전에 충분히 드러나지 않음.
   - 랭킹 참여 기본값은 비공개/미참여.
   - 닉네임과 구 단위만 공개하며 정확한 위치·경로·기분은 제외.
6. 로딩·빈 상태·오류 복구가 운영 화면과 분리되어 QA 비용이 큼.
   - MSW 시나리오 컨트롤에서 정상/느림/503/빈 상태를 전역 전환.
   - 추천 없음, GPS 오류, 중도 종료, 제휴 미션을 직접 진입 가능.
7. Figma의 가상 상태바는 네이티브 시스템 상태바와 중복됨.
   - 실제 iOS/Android StatusBar와 SafeArea를 사용.
8. 퍼플 본문색 일부는 작은 글자 대비가 약함.
   - 브랜드색은 유지하고 작은 본문에는 더 진한 `#5142C6`을 사용.

## QA 기준

- 모든 핵심 CTA, 탭, 입력, chip, toggle, 에러 재시도가 동작해야 함.
- iOS/Android/web에서 같은 정보 구조와 안전영역을 유지해야 함.
- Kakao 키가 없으면 QA 표시가 보이고, 사용자 흐름은 중단되지 않아야 함.
